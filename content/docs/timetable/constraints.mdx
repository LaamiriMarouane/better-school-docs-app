The generator follows two kinds of rules. Some are **always kept** and can't be switched off.
Others are **preferences** you tune per timetable group in **Solver policy**: you turn each one on
or off and decide how much it matters.

<Callout title="Who this is for">
Administrators tuning how the timetable generator behaves.
</Callout>

## Rules always kept

You don't configure these in Solver policy — the generator always follows them:

- No **class**, **teacher**, or **room** is in two places at once.
- No lesson is placed when its **teacher**, **room**, or **class** is marked unavailable (see
  [Scheduling setup](./scheduling-setup)).
- Each teacher stays within their **Max hours per day** and **Max hours per week**.
- A room is never used **beyond its capacity**, and a subject only uses rooms of the **right type**.
- No lesson is placed over a **break**, and a long lesson always sits in one unbroken block of
  periods.
- A class never has two separate lessons of the same subject on the same day (a double lesson
  counts as one).
- A subject is never placed at its **forbidden times**.
- Teachers only use rooms on their **Room whitelist**, and classes use the homerooms you set on
  **Homerooms**.
- Lessons linked with **Same slot** run at the same time.
- **Pinned** lessons stay exactly where you placed them.

If the generator can't place a lesson without breaking one of these, it leaves the lesson
unscheduled and tells you why. See [Generate and activate](./generate-and-publish).

## Open Solver policy

Open a **timetable group** (**Academic → Timetable → Groups** → open the group), click the **⋯**
menu in the group header, and choose **Solver policy**. The rules are grouped into tabs:
**Teachers**, **Classes**, **Subjects**, and **Lessons**.

Each preference has:

- an **on/off switch**,
- a value to set when the rule needs one (for example **Max gap**),
- an **importance** stepper — the higher it is, the harder the generator tries to satisfy this
  preference compared with the others,
- **Reset to baseline** to return that row to its default.

Click **Save** in the bar at the bottom of the tab to keep your changes, or **Discard** to drop
them.

### Teachers

| Preference | What it does |
| --- | --- |
| **Minimise teacher gaps** | Avoids free periods between a teacher's lessons on the same day. Set how many gaps are tolerated with **Max gap**. |
| **Teacher minimum periods per day** | If a teacher comes in on a day, they get at least this many periods that day. |
| **Teacher minimum periods per half-day** | The same, per morning or afternoon (needs the half-day divider). |
| **Teacher room stability** | Tries to keep a teacher in the same room across consecutive lessons. |

### Classes

The **Classes** tab has two sub-tabs:

- **Min periods** — the minimum periods per day and per half-day for each level, with optional
  overrides per class (**Revert to level** removes an override). Tick several levels or classes to
  set them together.
- **Constraint rules** — the class preferences below.

| Preference | What it does |
| --- | --- |
| **Minimise class gaps** | Keeps a class's day compact, avoiding free periods between lessons. |
| **Class room stability** | Tries to keep a class in the same room across consecutive lessons. |
| **Class minimum periods per day** | Avoids a class having a near-empty day. |
| **Class minimum periods per half-day** | Avoids a near-empty morning or afternoon. |

### Subjects

| Sub-tab | What you set |
| --- | --- |
| **Forbidden times** | Pick a subject and mark the periods it must never use — for example no PE in the first period. Always kept. |
| **Incompatibilities** | Pick a subject and the subjects it should not share the same day or half-day with. The **Subject incompatibility** row sets whether this preference is on and how much it matters. |
| **Chains** | Add pairs of subjects that should follow each other or share a day (**Add chain edge**). The **Subject chains** row sets whether this preference is on and how much it matters. |

### Lessons

Link specific lessons with **Add lesson link**, or use **Run two subjects in parallel** to pair the
groups of a split class across many classes at once. Links have four modes:

| Mode | Meaning |
| --- | --- |
| **Same slot** | Two lessons run at the same time, for different groups of a class. Always kept. |
| **Back-to-back** | Two lessons run in consecutive periods. |
| **Same day** | Two lessons fall on the same day. |
| **Same half-day** | Two lessons fall in the same morning or afternoon. |

**Back-to-back**, **Same day**, and **Same half-day** links all follow the **Lesson sequence** row:
its switch and importance apply to all of them together. See
[Lessons and assignments](./lessons-and-assignments).

<Callout title="Rules guide the generator, not your hands">
Solver policy only affects **Generate**. When you move lessons by hand, links and preferences never
block the move.
</Callout>

## Setting importance well

- **Start from the defaults.** They produce a sensible timetable for most schools. Only change
  what you specifically care about.
- **Don't push everything to the top.** Preferences compete — if everything is "most important",
  nothing is. Raise only the few that matter most to your school.
- **Tight rules leave lessons unscheduled.** Many forbidden times or incompatibilities can leave
  no room for some lessons. The unscheduled panel tells you when a subject rule is the cause.

<Callout title="Per-teacher overrides">
**Max gap periods**, **Min periods per day**, and **Min periods per half-day** can also be set for
one teacher in [Scheduling setup](./scheduling-setup) → **Teachers** → **Limits**. The teacher's own
value wins for that teacher.
</Callout>

## Common use cases

- **Compact days** — raise *Minimise class gaps* so students don't have idle periods.
- **Spread hard subjects** — use *Incompatibilities* to keep two demanding subjects off the same
  day.
- **Lab after lecture** — link the two lessons as **Back-to-back** and raise *Lesson sequence*.
