title: Create trips
description: Understand how daily trips appear automatically, how to add a trip by hand, and how to start, finish, re-crew, or cancel a trip.
---

A **trip** is one run of a route on a specific day — for example *North Line — Morning, on
Monday*. Trips are created **automatically** for you. You only add a trip by hand for
exceptions, such as a make-up day or an extra run.

<Callout title="Who this is for">
Administrators and transport coordinators who oversee daily bus operations.
</Callout>

## How daily trips appear

You don't add trips one by one:

- A trip is created for each **active route** on every **school day**. Holidays and school
  closures are skipped.
- Each trip starts with the route's **default vehicle and crew**, its **stops**, and the
  **students** assigned to it. A past trip keeps these details as they were that day, even if
  you change the route later.
- There is only **one trip per route per day** — you'll never get duplicates.

<Callout title="What you need for trips to appear">
A route only gets trips when it is **active** and has **stops** (and usually students). Make
sure the route is set up before you expect its trips to show up.
</Callout>

## Find a trip

Go to **Operations → Trips**. The page has three tabs:

| Tab | What it shows |
| --- | --- |
| **Live** | Trips that are running now. |
| **Scheduled** | Trips waiting to start. |
| **Completed** | Trips that have finished. |

Filter by date and by route, and switch between **Cards** and **Compact** views. Select a trip to
open its details next to the list, or **Open full view**.

## Create a trip by hand

Use this for a day that wouldn't normally have a trip — a Saturday make-up class, an exam day,
or a special outing.

<Steps>

<Step>
### Open Trips

Go to **Operations → Trips**, then click **Add trip**.

<Screenshot
  label="Trips page with the Add trip button"
  caption="Trips are shown on a calendar and a list. Filter by route, driver, or status."
/>
</Step>

<Step>
### Fill in the trip details

| Field | Required | Notes |
| --- | --- | --- |
| **Route** | Yes | The route to run. Its stops and students are copied onto the trip. |
| **Service date** | Yes | The day the trip runs. |
| **Planned start time** | No | When the bus is due to leave. |
| **Vehicle** | No | Overrides the route's default vehicle for this trip only. |
| **Driver** | No | Overrides the route's default driver for this trip only. |
| **Assistant** | No | Overrides the route's default assistant for this trip only. |

A vehicle or crew member already on another trip at that time is marked **Busy** so you can
choose someone else.
</Step>

<Step>
### Create

Click **Create**. The trip appears under **Scheduled**, ready for the crew to start.
</Step>

</Steps>

<Callout title="One trip per route per day">
You can't create a second trip for the same route on the same day. If a trip already exists,
open that one instead.
</Callout>

## Run a trip

Usually the crew runs the trip from their own **Trips** page (see
[Trip attendance](./trip-attendance)):

1. **Start** — the driver or assistant starts the trip on its day. It moves to **Live**. A trip
   needs a driver or an assistant before it can start.
2. **Mark students** — at each stop, the crew marks who boarded or was dropped off.
3. **Finish** — the trip completes on its own once every student is marked and every stop is
   done, or the crew taps **Finish trip**. A drop-off trip can't finish while a student is still
   on the bus. If the bus can't complete the route, the crew can use **End trip (emergency)**.

If a trip is left running after its day, it is closed automatically and any student still
unmarked is recorded as **No show**. A trip that never started stays under **Scheduled** until an
administrator cancels it.

## Manage a trip from the office

Open a trip and use its **⋯** menu:

| Action | When |
| --- | --- |
| **Start trip** | On a scheduled trip, on its day — for example if the crew can't start it themselves. |
| **Complete trip** | On a live trip, to close it by hand. Students still unmarked are recorded as **No show**. |
| **Change crew** | Swap the driver, assistant, or vehicle for this trip only. People or vehicles already busy are flagged. The route's defaults are unchanged, so the next trip goes back to the usual crew. |
| **Cancel trip** | The trip won't run. Enter a **Reason**. Parents are told the bus isn't running today, and attendance already marked is kept. A cancelled trip can't be restarted. |

Only administrators can change the crew; drivers and bus monitors can't.

## Common use cases

- **Normal day** — do nothing; trips appear automatically.
- **Saturday make-up day** — add a trip by hand for that date.
- **Driver off sick** — use **Change crew** on the affected trips.
- **Snow day** — cancel the day's trips with a reason.
